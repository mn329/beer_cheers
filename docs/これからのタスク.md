## 優先順（合意どおり）

### 1. リモート同期の信頼性（作業順 A）

- [x] 二重再生・自分エコーの再確認（現状の抑制が十分か）→ pending を不一致で捨てず、一致 or 3秒タイムアウトまで保持（`CheersRemoteSync`）
- [x] 部屋切替直後に古い部屋の trigger を拾わないか確認 → `listenGeneration` + `stopListening` で `currentRoomID`/`keepSynced(false)` 清掃
- [x] ネットワーク失敗時もローカル演出は出す（先に `triggerCheers`、後で publish。順序維持）
- [x] **リモート未達時のエラー表示** → `RootTabView` 共通バナー（Firebase 未初期化 / 未入室 / `setValue` 失敗）。クールダウンスキップはエラーにしない
- [x] 「数秒以内」の体感確認し、足りなければスロットル／監視を調整（`writeCooldown` は当面 1.5s のまま。実機で問題なし）
  ※ 実機2台は必須にしない。代替手順でも可。

#### 同期確認チェックリスト

**確認結果（2026-09-17）:** 実機動作問題なし。スロットル調整は不要。

**推奨代替（いずれか・再確認用）**

| 方法 | できること | 注意 |
|------|------------|------|
| シミュレータ + 実機1台 | 送受信の体感・数秒以内 | 同一 Firebase プロジェクト・同一ルーム |
| シミュレータ2台 | 送受信・エコー | モーションはシミュレで振れない → 片方は Watch 連携なしならデバッグ用に手動乾杯が必要かも |
| 実機1台 + Firebase Console | 受信側（リモート trigger） | Console で `rooms/{roomID}/trigger` に `{ "ts": <unix>, "id": "<uuid>" }` を書く |

**1台だけで確認できる項目**

1. 自分エコーなし（1台で乾杯 → 演出は1回。コンソールに「自分エコー抑制」）
2. 部屋 A→B 切替直後に古い trigger で誤再生しない
3. Airplane Mode → 自分は演出あり + 「相手への同期に失敗しました」バナー
4. 通信復帰後に再度 `setValue 成功` が出る
5. （任意）Zoom/FaceTime 併用は実機1台でも「通話中に振る」程度は確認可

**2クライアントが必要な項目（代替で代替可）**

6. 片方の乾杯 → もう片方で数秒以内に演出（Sim+実機 / Sim×2 / Console 手書き）
