## 優先順（合意どおり）

### 1. リモート同期の信頼性（作業順 A）

- [ ] 二重再生・自分エコーの再確認（現状の抑制が十分か）
- [ ] 部屋切替直後に古い部屋の trigger を拾わないか確認
- [ ] ネットワーク失敗時もローカル演出は出す（現状ほぼそう）
- [ ] **リモート未達時のエラー表示**（合意の新規。乾杯画面 or 共通バナー）
- [ ] 実機2台で「数秒以内」を体感確認し、足りなければスロットル／監視を調整

### 2. メンバー一覧の分かりやすさ（作業順 C）

- [ ] 入室直後に「誰がいるか」が一目で分かるか見直し
- [ ] 表示名・絵文字の反映タイミング（プロフィール保存 → ルーム表示）の確認
- [ ] 読み込み中 / 空状態の文言・見た目の整理
- [ ] （任意）ホスト表示と「自分」ラベルの視認性

### 3. ルーム参加の簡単さ + URL（作業順 B）※新規大きい

- [ ] ルーム用 URL スキーム（または Universal Link）の設計
- [ ] URL を開く → **参加確認ダイアログ** → 入室（この経路は PW 不要）
- [ ] ルーム画面から URL / 共有テキストをコピーできる UI
- [ ] 名前参加時のみ任意パスワードを維持（URL 経路と矛盾させない）
- [ ] （できれば）ルーム名の正確一致検索 UI
- [ ] （できれば）最近入った部屋の履歴

### 4. Watch デモの安定化（作業順 E）

- [ ] Watch タップ → iPhone 受信 → ローカル演出 → リモート同期の通し確認
- [ ] iPhone アプリが前面にいないときの挙動を確認・文書化
- [ ] デモ手順を短く書く（iPhone 核 → 後半に Watch）

### 5. ローカル演出（作業順 D）※当面は後回し可

- [ ] 誤検知・振りやすさの調整（合意では様子見）
- [ ] 音・触覚・泡の体感ブラッシュアップ

### 6. 認証（G）※ MVP の核ではない／約束しない

合意: **ログインなしで Done**。メール／パスワード認証は「あるとよい任意機能」として扱う。核の説明・デモの主役にしない。

#### 方針を守る（必須に近いチェック）

- [ ] 未ログインでもルーム作成・参加・乾杯同期・メンバー一覧が使えることを回帰確認
- [ ] 認証 UI が乾杯／ルーム導線をブロックしていないか確認（必須ログイン画面にしない）
- [ ] README・デモ説明で「ログイン必須」と誤解されない文言にする

#### 任意機能としての磨き（できれば）

- [ ] サインイン／アカウント作成／サインアウトのエラー表示を分かりやすくする
- [ ] パスワード要件（6文字以上など）とバリデーション文言の整理
- [ ] サインイン状態とプロフィール（表示名）の関係を整理する（Auth の displayName とローカルプロフィールの優先）
- [ ] 認証状態の復帰（再起動後も signed-in が維持されるか）確認
- [ ] （将来）Realtime Database ルールを認証必須へ締める場合の移行方針をメモする ※今の MVP Done とは別フェーズ

#### ブランチ例

`feat/auth-optional-polish`（`dev` から。MVP 穴埋め A〜B より後でよい）
